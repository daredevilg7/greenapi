# Проверка проекта

Проверено 4 октября 2026 года. Node.js 22.20.0, npm 11.7.0.

## Автоматические проверки

Финальный прогон после исправлений:

- `npm test` — **36 тестов, 7 файлов, все проходят**.
- `npm run test:api` — **7 интеграционных тестов через настоящий локальный HTTP-сервер проходят**. Клиент отправляет реальные HTTP-запросы; глобальный `fetch` не подменяется.
- `npm run build` — **TypeScript и Vite проходят**, создан `dist/index.html`.
- TypeScript проверяет также HTTP-тесты, реальный API-прогон и его отдельную конфигурацию.

Проверки охватывают номера и текст, ограничения адреса API, обработку уведомлений и статусов, дедупликацию, порядок получения и подтверждения квитанции, повтор подтверждения после ошибки, отмену запросов и защиту от событий предыдущей сессии. Интеграционные тесты проверяют выбор устройства, демонстрационную отправку, сохранение сообщения при переключении и создание чата.

Независимый обзор выявил гонки между повторной отправкой, исходящим уведомлением и поздним HTTP-ответом. Добавлены три регрессионные проверки: ошибочный старый запрос не присваивает себе идентификатор нового сообщения; неоднозначные одинаковые отправки не сопоставляются автоматически; позднее принятие в очередь не стирает подтверждённую ошибку доставки. Все три проверки сначала воспроизводили ошибку, после исправления проходят.

## Проверка в браузере

Локальное приложение открыто в браузере Codex. Размеры области страницы: 1440 × 1000, 390 × 844 и 667 × 320. Последний размер моделирует ограниченную высоту; настоящая клавиатура iOS и физическое устройство отдельно не проверялись.

Подтверждены:

- Экран выбора телефона и компьютера, форма подключения и демонстрационный вход.
- Светлый десктопный MAX и тёмная переписка «Корпоратив» внутри корпуса iPhone.
- Отправка текста Enter, новая строка Shift + Enter и появление демонстрационного ответа.
- Сохранение переписки и черновика при переключении устройств.
- Новый контакт: ошибка короткого номера, создание по форматированному номеру РФ с именем.
- Выбор и отправка эмодзи, поиск контакта и поиск текста в переписке.
- Узкий десктопный режим со списком/перепиской и доступом к настройкам через шапку чата.
- Escape закрывает диалог и возвращает фокус на открывшую его кнопку.
- Ошибка некорректных ключей подключения без сетевого запроса.
- Отсутствие горизонтального переполнения на узком экране, доступное поле ввода на низком экране.
- Автоматическое положение у последних сообщений при смене чата и размеров области переписки.

В ходе браузерной проверки исправлено чрезмерное уменьшение корпуса телефона при маленькой высоте. Теперь страница прокручивается, сохраняя пригодный для ввода размер. Добавлено наблюдение за размером переписки, чтобы последние сообщения оставались видимыми при изменении доступного пространства.

Первый браузерный прогон завершился без ошибок приложения. После переработки отдельно проверено подключение с предоставленным ключом: интерфейс корректно показал сетевую ошибку без вывода токена. Журнал сетевой панели с URL, содержащими ключ, не сохранялся.

## Что требует реального инстанса

Пользователь предоставил ключи инстанса. `npm run test:api:live` выполнен с ними и завершился ошибкой соединения на `getStateInstance`. Прямые запросы из Node.js и curl, а также подключение из браузера не получили HTTP-ответ: TLS-соединение обрывается (`ECONNRESET` / `SSL_ERROR_SYSCALL`). DNS официальных хостов разрешается. Причина сброса соединения с этой сетью не установлена; действительность ключа не подтверждена.

На предоставленном пользователем скриншоте указан статус «Неавторизован». Актуальное состояние через API прочитать не удалось. Номер тестового получателя ещё не предоставлен. Реальные `checkAccount`, отправка, ответ получателя и статусы доставки **не подтверждены сквозным прогоном**; реальные сообщения не отправлялись. Обычные интеграционные тесты обращаются к локальному HTTP-серверу с тестовыми ответами.

Реальный прогон имеет режимы `read`, `send`, `roundtrip` и отдельную команду `test:api:receive`. Последняя проверяет ответ на уже отправленное сообщение, не создавая новую отправку. Маркер сохраняется также при неоднозначном результате отправки; автоматического повторения нет.

Для сквозной проверки: подключить MAX-инстанс с настройками из README, создать чат с доступным по номеру получателем, отправить текст, ответить из MAX и убедиться, что ответ появился в приложении. Подключение не меняет настройки инстанса автоматически.

Удалённый репозиторий и сервер пользователь предоставит позже. Проект не публиковался; готовая статическая сборка находится в `dist/`.


## Переработка по обратной связи

Убран рекламный экран с большой типографикой, наклонёнными искусственными превью и декоративными эффектами. Выбор устройства стал простым экраном MAX. Сохраняются исходные сценарии подключения и переключения.

Десктоп сверен с предоставленным скриншотом при размере страницы 1266 × 694 (высота референса без браузерной панели): левая панель 70 px, список 354 px, шапка чата 58 px, поле сообщения 640 px. Восстановлены состав панели, фон с тайлом 280 px, размеры сообщений, оригинальный логотип и аватары из референсов. Вложения и звонки показаны для узнаваемости интерфейса; их кнопки отключены с пояснением о текстовом задании.

Мобильный режим проверен при 1360 × 1360 и 390 × 844. Корпус масштабируется вместе с внутренним интерфейсом; в размере большого референса ширина корпуса 560 px, текст сообщений 25.47 px. На узком экране ширина поля сообщения 215.79 px, горизонтального переполнения нет. Проверены демонстрационная отправка, появление ответа и переход на узкую веб-версию с сохранением переписки. Демонстрационные сообщения дополняют текстовую переписку; голосовые сообщения, стикеры и реакции не имитируются.

Полный токен проверен на отсутствие в `src/`, `public/`, `dist/` и `docs/`: PASS. Ключи для живого теста находятся только в игнорируемом `.env.live`; отчёты и защита от повторной отправки — в игнорируемой `.local/`.
